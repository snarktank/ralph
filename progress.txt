# Ralph Progress Log
## Codebase Patterns
- Non-destructive CLI modes in `ralph.sh` should parse and exit before validating tool binaries, prompt files, or Ralph state so help and future recovery commands work even on broken setup.
- Doctor-style diagnostics should validate `prd.json` directly, but treat `progress.txt` and `archive/` as lazily created state paths and check readiness instead of requiring them to exist.
- Inspection modes should print the absolute Ralph state paths before summary or recovery guidance so users can act without opening `ralph.sh`.
- Fatal CLI errors should identify the exact missing binary or file and finish with the repo-local recovery command path, such as `./ralph.sh --help`, `./ralph.sh --doctor`, or `$prd -> $ralph -> ./ralph.sh`.
